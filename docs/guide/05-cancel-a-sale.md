# Cancel a sale

Something was rung up wrong and the customer is still at the counter. Voiding the sale puts the
stock back, takes the money off the drawer, and leaves a record of what happened.

**Before you start:** voiding is for a mistake caught the same day, on the same shift. If the
customer is bringing goods back later, that is a sale return instead — ask whoever runs the
shop.

## Steps

1. From the menu, choose **Sales**.
   Every invoice is listed, newest first.
   <img class="shot-full" src="images/sales-list-desktop.png" alt="The Sales list showing invoices with their reference, date, customer, total and status">

2. Find the invoice. The reference is on the receipt, and starts **SL_**.

3. Open it and choose to void it.

4. Type why. "Wrong item rung up" or "Customer changed their mind" is enough.
   The reason is kept with the invoice, so write something a person reading it next month will
   understand.

5. Confirm.
   The invoice stays on the list, now marked **voided**.

## What happens next

Three things happen together:

- The stock goes back on the shelf.
- The money comes off the drawer, so your closing count still balances.
- The books are reversed, so the sale no longer counts as income.

**The invoice is not deleted and its number is not reused.** That is deliberate: the BIR expects
an unbroken run of invoice numbers, and a missing number looks worse than a voided one. The
voided invoice still appears in the day's range on the Z-reading.

## If it does not work

| You see | It means | Do this |
|---|---|---|
| **That sale has already been voided.** | somebody voided it already | check the status on the list; no further action is needed |
| **That shift has already been counted down. Use a sale return instead.** | the till was closed after the sale | the drawer is settled, so this has to go through as a return |
| **That sale was not made today. Use a sale return instead.** | the sale is from an earlier day | same — handle it as a return, not a void |
| **Void reason is required** | you left the reason blank | type why it is being voided |

If you cannot void it, that is usually correct rather than a fault: once the drawer is counted
and closed, changing what was in it would make the count wrong after the fact.
